# Assistara Academy — Visual Lesson Standard

**Status:** Binding production + remediation standard  
**Applies to:** every existing and future learner-facing class  
**Read with:** `docs/academy/LESSON-SYSTEM.md` and `assistara-local-v9/academy/LESSON_SLIDE_PRODUCTION_STANDARD.md`

## 1. Core rule

An Assistara class must **look taught, not merely written**.

Correct copy placed into headings, paragraphs and repeated cards is not enough. The learner should be able to scan the page and understand the structure, process and important ideas visually.

Design every class around:

**EXPLAIN → SHOW → DEMONSTRATE → PRACTICE**

For every major teaching section ask:

> Would the learner understand or remember this faster if we showed it?

If yes, build the visual explanation.

## 2. What counts as visual teaching

Choose the representation that fits the content. Examples include:

- process maps and workflows
- annotated realistic UI/mock interfaces
- before/after transformations
- decision trees and branching choices
- timelines and step sequences
- hierarchy/folder diagrams
- client-message and email examples
- calendar, task-board and research mockups
- comparisons and do/don't examples
- scenario cards
- status flows and mini infographics
- labeled illustrations
- source-to-deliverable diagrams
- useful icons supporting actions/categories

A colored card containing ordinary paragraph text is **not automatically a visual**.

Decorative imagery, gradients, icons or illustrations may support the composition, but they do not satisfy the visual-teaching requirement by themselves.

## 3. Real remote-work context

Prefer concrete client-work artifacts over abstract explanation whenever the source supports them.

Email lessons should resemble inboxes, filters, messages and replies. Calendar lessons should show schedules, conflicts and time decisions. File lessons should show folder structures, filenames and permissions. Task/project lessons should show owners, priorities, due dates and status movement. Research lessons should show source → finding → synthesis → report. Client communication should show realistic conversations and stronger/weaker responses.

The learner should repeatedly see what professional remote work looks like.

## 4. No walls of text

Avoid long uninterrupted passages. When appropriate, use a rhythm such as:

**concept → visual example → explanation → client situation → takeaway**

Keep paragraphs readable. Do not solve excessive copy by splitting the same prose across several identical cards.

## 5. Visual rhythm, not card repetition

A lesson page should not become:

CARD → CARD → CARD → CARD → CARD.

Vary composition according to meaning: editorial explanation, large teaching visual, split example, workflow, comparison, scenario, callout, practice, recap.

Reuse a component when it is genuinely the clearest tool; never vary layout merely for novelty.

## 6. Before/after and process are core devices

When the source teaches improvement or transformation, show it. Examples: messy → organized inbox, vague → actionable task, weak → professional message, random → structured files, raw research → client-ready report.

When the source describes a sequence, consider a visual process instead of a numbered paragraph list. If the process branches, show the decision points rather than pretending it is linear.

## 7. Interaction must help learning

Where technically appropriate, useful interactions can include reveal-answer examples, scenario choices, expandable explanations, before/after toggles, clickable stages and lightweight practice.

Do not add interaction solely to make a page feel busy.

## 8. Class-specific design

Do not copy the previous class automatically. First identify what THIS learner must understand or do, then choose the visual language that best teaches it.

The established Academy examples and Google Workspace Navigation reference set the **quality bar and visual language**, not a fixed layout template.

Every class should feel like Assistara without every class looking the same.

## 9. Brand + space

Preserve the established Assistara system: Manrope, approved logo/identity, cream, near-black, Assistara yellow and restrained sage/peach, with strong hierarchy and spacing.

Large empty areas are acceptable only when intentional. If a section looks unfinished, reconsider the composition: enlarge a meaningful teaching visual, change the layout, add a source-grounded example, or restructure the section. Never fill space with meaningless decoration.

Use consistent iconography rather than random emoji as the primary visual system.

## 10. Lesson page and slides are different

The lesson page and teaching deck share a visual language but serve different purposes.

Do not copy the written lesson onto slides. Slides should be even more visual and concise: diagrams, large examples, comparisons, mock interfaces, processes and demonstrations.

The canonical learner-facing slide artifact remains the established landscape 16:9 PDF and must follow the binding slide-production standard.

## 11. Mobile is part of the design

Every teaching visual must remain understandable on mobile. Never accept microscopic text, horizontal overflow, broken diagrams, accidental blank areas or desktop grids squeezed into a phone.

Complex desktop compositions must intentionally stack or recompose. QA approximately 375px, 390px and 430px where tooling permits.

## 12. Source fidelity remains binding

Visual improvement does not permit curriculum invention.

Read the approved guidebook section before redesigning a class. Visuals translate source-supported teaching into clearer learning; they must not introduce unsupported frameworks, claims or requirements.

## 13. Mandatory visual QA

A class does not pass visual QA merely because it renders.

Inspect the complete learner-facing class and ask:

- Is the first screen visually engaging and purposeful?
- Can the lesson structure be understood by scanning?
- Are important concepts shown rather than merely described?
- Are examples realistic and source-grounded?
- Is there meaningful composition variety?
- Is any section a wall of text?
- Are “visuals” actually just prose in cards?
- Does the class feel professionally designed?
- Does it match the quality level of the approved Assistara reference without copying it?
- Are desktop and mobile layouts legible and intentional?
- Are interactions, Quick Check, completion and progression still intact?

Fix what fails, re-render/reinspect, then record the QA honestly.

## 14. Existing-class remediation is mandatory

This standard applies retroactively to **all existing learner-facing classes**, not only Phase 1 Module 5.

Audit existing classes in curriculum order. For each class:

1. Read the corresponding approved source section.
2. Open and inspect the current implementation.
3. Inspect the rendered learner experience.
4. Identify text-heavy or visually weak sections.
5. Decide which concepts deserve visual teaching.
6. Redesign only what materially improves learning.
7. Preserve correct source content and working functionality.
8. Inspect desktop and mobile.
9. Re-test Quick Check, completion and progression when touched.
10. Record the remediation/QA result before continuing.

Do not blindly redesign already-strong sections.

## 15. Phase 1 Module 5

Phase 1 Module 5 is a known visual-remediation priority. Its classes must be brought to this standard, but do not create a one-off Module 5 design language. The same quality threshold applies Academy-wide.

## 16. Definition of done

A class is not finished merely because content, slides, icons and a Quick Check exist.

It is finished only when content accuracy, teaching design, meaningful visuals, responsiveness, interaction, progression and polish form one coherent learning experience.

Target feeling:

**“Someone designed how I should understand this.”**

Not:

**“Someone uploaded course text to a website.”**
